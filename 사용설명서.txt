GFL2 Guild OCR v0.1.3 사용설명서
Windows 64비트
App Version 0.1.3 / Database Schema v5

첫 실제 실행은 사용자가 직접 합니다. 실제 DB의 별도 수동 사전 백업과 SHA-256 일치를 확인하세요.
Schema v4 → v5 migration 및 최근 4주보다 오래된 공적 기록/Raw/State/Choice/CSV 정리가 발생할 수 있습니다.
흙먼지 history는 공적 정리 대상이 아닙니다. 문제가 있으면 앱을 종료한 뒤 문의하세요.
구버전 EXE만 실행하면 DB도 복구된다고 가정하지 마세요. 실제 DB 복원은 별도 확인 후 진행합니다.

1. 프로그램 소개

GFL2 길드의 공적 및 흙먼지 화면을 OCR로 읽고, 길드원별 주간 점수를 관리하는 Windows 프로그램입니다. 공개 배포 ZIP에는 실행에 필요한 구성 파일이 포함되어 있으므로 Python을 따로 설치할 필요가 없습니다.

2. 다운로드 및 설치

공식 다운로드:
https://github.com/busikang/gfl2-guild-ocr-releases/releases/tag/v0.1.3

GFL2GuildOCR-v0.1.3-win-x64.zip을 다운로드하여 원하는 위치에 전체 압축을 풉니다. 압축을 푼 GFL2GuildOCR 폴더 안에서 GFL2GuildOCR.exe를 실행하세요. EXE만 다른 곳에 복사하거나 _internal 폴더를 삭제하지 마세요. 이 설명서는 ZIP에도 포함되어 있습니다.

3. 프로그램 실행

처음 실행하면 공적치 계산, 흙먼지 계산, 과업 주간, 흙먼지 주간, 길드원 관리 탭이 표시됩니다. 사용자 기록은 프로그램 설치 폴더가 아닌 별도 데이터 폴더에 저장됩니다. 처음 실행 시 Windows 보안 경고가 나타나면 파일의 다운로드 출처를 공식 배포 페이지에서 확인한 뒤 실행 여부를 결정하세요.

4. 기본 사용 순서

게임 창에서 읽을 화면을 연 다음 공적치 계산 또는 흙먼지 계산 탭으로 이동합니다.

  ① 창 목록에서 게임 창 선택
  ② 선택 창 캡처 + OCR 클릭
  ③ OCR 결과에서 닉네임과 숫자 확인, 필요한 셀을 더블클릭하여 수정
  ④ 길드원 관리에서 미등록 이름이나 잘못 읽힌 별칭 확인
  ⑤ 해당 과업 주간 또는 흙먼지 주간 탭에서 현재 OCR 결과를 오늘 반영 클릭
  ⑥ 주간 시트의 점수와 확인 필요 표시 확인

이미 저장한 PNG/JPG를 쓰려면 이미지 불러오기를 누른 뒤 한국어 OCR 실행을 누릅니다. 이미지 파일을 불러오는 것과 달리 선택 창 캡처 + OCR은 캡처 직후 OCR을 자동으로 실행합니다. 여러 화면을 스크롤하며 캡처한 경우 이름이 같으면 기존 OCR 결과 행에 반영됩니다. 결과를 주간 시트에 반영하기 전에 닉네임과 수치를 확인하세요.

5. OCR 화면 읽기

공적치 계산 탭은 게임의 '이번 주 공적'을 일일 공적 계산에 사용합니다. 이는 공적 화면에서 닉네임 뒤에 보이는 첫 번째 OCR 숫자입니다. 두 번째 '누적 공적'은 주간 경계에서 이전 일요일을 검증할 때만 사용합니다.

흙먼지 계산 탭은 게임의 '누적 점수'를 관리 계산에 사용합니다. 이는 흙먼지 화면의 두 번째 OCR 숫자입니다. 첫 번째 '단일 전투 최고 점수'는 일일 관리점수의 입력값이 아닙니다.

OCR 결과 표에서는 셀을 더블클릭해 잘못 읽힌 글자나 숫자를 고칠 수 있습니다. 행 추가와 선택 행 삭제도 가능합니다. 이미지를 작게 보여 주는 미리보기 크기는 OCR에 사용하는 원본 해상도를 줄이지 않습니다. 화면을 캡처할 때 게임 화면에 올바른 목록이 표시되어 있는지 확인하세요.

6. 게임 날짜와 주간 기준

게임 하루는 오전 05:00에 바뀝니다. 실제 시각 00:00~04:59에 반영한 기록은 전날 게임 날짜로 들어갑니다.

과업 주간은 월요일 05:00부터 다음 주 월요일 04:59까지입니다. 흙먼지는 개시선언으로 시작하는 이벤트이며 일요일 05:00부터 다음 주 일요일 01:59까지입니다. 일요일 02:00~04:59에는 새 개시만 금지합니다. 종료 이후 최종 OCR 반영과 결산은 가능합니다. 21일 경과로 자동 개시하지 않으며 이전 이벤트도 조회할 수 있습니다.

7. 길드원 관리

처음 보이는 OCR 이름은 자동으로 길드원으로 등록되지 않습니다. 길드원 관리 탭의 새 길드원 등록으로 등록하거나, 선택 미등록 이름 연결로 기존 길드원에게 연결합니다. 검색, 탈퇴 포함, 새로고침으로 목록을 살펴볼 수 있습니다. 닉네임을 우클릭하면 길드원 등록·연결·대표 닉네임 수정·별칭 관리·탈퇴·복귀·기록 보기 등의 메뉴가 상태에 맞게 표시됩니다.

8. 과업 주간 사용법

공적치 계산 탭에서 OCR 결과를 확인한 후 과업 주간 탭에서 현재 OCR 결과를 오늘 반영을 누릅니다. 주간 시트의 하루 공적은 같은 주의 '오늘 이번 주 공적 - 직전 정상 이번 주 공적'입니다. 월요일에 처음 확인한 값은 주간 시작값 0에서 계산합니다. 예를 들어 월요일 11,971, 화요일 23,942라면 표시되는 하루 공적은 각각 11,971입니다. '누적 공적' OCR 숫자를 여기서 빼지 않습니다.

새 과업 일일 기준은 조회 중인 주간마다 따로 적용합니다. 적용하지 않은 주는 기존 계산을 유지하며, '미설정 (기존 계산)'을 적용하면 해당 주를 기존 계산으로 되돌립니다. 일반은 90으로 고정되며, 흙먼지와 개척원정에 입력하는 값은 기본 90을 이미 포함한 일일 총 cap입니다. 이후 OCR 증가분이 직전날의 자동 계산 점수나 누락일에 배분될 수 있으며, 사용자가 수동 확정한 점수는 자동 변경되지 않습니다. 월요일의 실제 창 캡처 OCR에서 확인한 누적 공적은 이전 일요일의 최종 점수를 검증하는 데 사용할 수 있습니다. OCR 원본과 실제 채택 기록은 다시 쓰지 않습니다.

흙먼지 이벤트 선언 기록이 있는 경우, '흙먼지' 과업 기준의 총상한은 선언된 이벤트 시작일~마지막 게임 날짜에만 적용하고 이벤트 밖 날짜는 일반 총상한 90으로 계산합니다. 이벤트가 일요일에 시작하면 그 전 월~토요일은 90이며, 일요일 증가분을 토요일에 이벤트 상한만큼 넘기지 않습니다. 선언 기록이 없는 기존 주간은 종전의 주간 전체 기준을 유지합니다. '흙먼지 / 90'은 미참여 기준 90이 아니라 일일 총상한 90을 저장한 상태입니다. 실제 이벤트 총상한을 확인하여 해당 주간에 직접 적용해야 하며 프로그램은 상한을 자동으로 올리지 않습니다.

주간 종료 시 상한을 넘으면 확인 필요 상태의 근거에 날짜·계산 일일 점수·적용 총상한이 표시됩니다. 이 때문에 흙먼지 계산이 대기 중이면 공적의 미확정 사유도 함께 표시합니다. Accepted 기록 선택창은 기록이 1건인 경우 기록 충돌이 아님을 안내하며, 같은 기록을 다시 선택해도 상한이나 OCR 근거 문제가 해결되는 것은 아닙니다.

주간 공적이 이전 정상값보다 감소하면 자동으로 0점이라고 처리하지 않고 확인 필요 상태로 둡니다. 새 기준을 적용한 주에도 현재 날짜의 미배분 잔여 점수는 일시적으로 cap을 넘을 수 있으며, 다음 OCR 또는 주간 마감 근거로 검증합니다. 색상은 하루 공적 50 미만 빨강, 50 이상 90 미만 노랑, 90 이상 초록입니다. 흙먼지의 참여 판정에 쓰이는 '흙먼지 미참여 공적 기준' 기본값은 90으로, 과업 일일 총 cap과는 별개입니다.

9. 흙먼지 주간 사용법

흙먼지 계산 탭의 두 번째 숫자인 누적 점수를 확인합니다. 진행 중인 이벤트가 없으면 흙먼지 주간에서 개시선언을 먼저 합니다. 진행 중(ACTIVE)에는 현재 OCR 결과를 오늘 반영합니다. 기본 하루 점수는 오늘 누적에서 직전 유효 누적을 뺀 값입니다. 기존 수동(MANUAL) 점수와 누적 복원 규칙을 유지하며 서로 다른 이벤트의 누적 기준을 섞지 않습니다.

종료 후 결산 대기(SETTLEMENT_READY)에서는 게임의 랭킹 화면을 새로 선택 창 캡처 + OCR한 뒤 현재 OCR 결과를 최종점수에 반영합니다. 원본 관측시각이 종료 시각 이상이고 시간대 정보가 있어야 합니다. 가져온 이미지나 종료 전에 캡처한 OCR을 남겨 두고 버튼만 누르는 경우는 거부합니다. 여러 행 중 하나라도 부적격이면 전체 반영을 취소합니다. 종료 후 최종 OCR은 실제 캡처 시각을 보존하면서 해당 이벤트의 마지막 토요일 점수에 반영됩니다.

마지막날 자동 복원은 최종 누적에서 신뢰 가능한 기존 일별 점수 합계를 뺀 차액으로 계산합니다. 기존 주간 시트의 일일 점수도 근거로 사용할 수 있습니다. 조건이 맞으면 전날의 기존 0점 또는 부분점수를 일일 최대점수까지 우선 채우고 남은 차액을 마지막날에 배분합니다. 전날 기록이 없으면 전날+오늘 두 날짜 범위에서만 복원하며 전전날까지 연쇄 배분하지 않습니다. 공적 참여 조건, 수동 점수, 기준 누적(BASELINE), 별칭 충돌 및 누적 모순은 계속 보호합니다. 특히 MANUAL 0점은 자동으로 최대점수로 바뀌지 않습니다.

최종 OCR이 성공했고 필요한 일일 점수와 별칭 충돌이 모두 해결되면 결산 확정을 진행합니다. 최종 OCR이 없으면 결산은 차단됩니다. 결산 완료(FINALIZED)는 탈퇴일까지 확정 점수를 합산한 snapshot을 보존하며 OCR/재결산이 비활성화됩니다. 다음 이벤트는 새 개시선언으로 시작합니다.

이벤트 중 탈퇴자는 닉네임 [탈퇴]와 회색으로 표시하고 탈퇴 다음 게임일부터 X입니다. 탈퇴일까지 점수는 결산에 포함되며 과거 이벤트의 탈퇴 정보는 보존됩니다.

기존 DB에 2026-09-20~09-26 흙먼지 근거가 있으면 legacy 이벤트가 연결됩니다. 종료 후에는 일반적으로 결산 대기 상태가 예상됩니다. legacy도 종료 후 새 창 캡처 최종 OCR이 필요하며, 실제 DB 조건이 다르면 상태를 강제로 맞추지 않습니다.

'일일 최대점수'와 '점수컷'은 각각 숫자를 입력하고 옆의 적용을 눌러 설정합니다. 일일 최대점수를 넘는 계산 결과를 임의로 잘라 점수를 버리지 않습니다. 근거가 부족하거나 상한을 넘는 경우에는 확인 필요 상태로 남겨 사용자가 원인을 살펴보게 합니다. 점수컷보다 낮은 확정 일일 점수는 빨강, 점수컷 이상은 초록으로 표시됩니다. 흙먼지 계산에는 과업의 참여 여부도 영향을 줍니다.

10. 미확정 점수와 근거 확인

주간 시트의 빈칸은 그 날짜에 관리할 기록이 없다는 뜻입니다. X는 가입 전 또는 이벤트 탈퇴 다음날 이후처럼 관리 대상이 아닌 날짜에 표시됩니다. '…'는 관측값은 있지만 아직 확정되지 않은 진행 상태, '?'는 서로 다른 근거나 계산 조건 때문에 확인이 필요한 상태입니다. '0?'는 관측된 0이지만 아직 확정되지 않았다는 뜻이며, 그냥 '0'은 확정된 0점입니다. '? 누적179565'처럼 보이는 숫자는 OCR에서 확인한 누적값이지 확정된 하루 점수가 아닙니다. 점수 셀에 마우스를 잠시 올리면 상태와 근거를 볼 수 있습니다.

미확정 최종일의 '? 차액63,493'은 '최종 누적 - 현재 신뢰 가능한 기입 점수 합계'로 남은 설명되지 않은 점수입니다. 확정 Daily나 오늘 입력해야 할 점수 자체가 아닙니다. Tooltip/상태·근거 상세에는 기입 합계, 최종 누적, 차액, 전날·오늘 배분 후보와 자동 확정 불가 이유가 표시됩니다. 차액이 음수이거나 두 날짜 최대점수 합보다 크면 임의로 잘라 확정하지 않습니다. 미확정 주간 합계는 '?'로 남습니다. 자동 복원 성공 행은 실제 숫자만 표시하고 전체 일별 합계가 최종 누적과 일치해야 합니다.

흙먼지에서 전날 OCR 또는 기존 기록에 신뢰 가능한 누적값이 있고, '오늘 누적 - 전날 누적'이 정상 범위라면 해당 셀을 더블클릭하거나 우클릭한 뒤 '전날 OCR 근거 확인 후 점수 반영'을 선택할 수 있습니다. 팝업의 전날 누적, 오늘 누적, 계산된 하루 점수, 일일 최대점수를 검토하고 확인 체크를 한 다음 반영하세요. 이때 전날 누적은 오늘 계산의 기준점으로 확인하는 것이며, 전날 하루 점수를 새로 만들어 넣는 것이 아닙니다. 근거가 맞지 않거나 상한을 넘으면 무리하게 확정하지 말고 OCR 결과와 길드원 연결부터 확인하세요.

11. 점수 직접 수정

주간 시트에서 점수 셀을 더블클릭하거나 우클릭합니다. 상태에 따라 '점수 수정' 또는 '점수 수동 확정', '상태 / 근거 보기', '관련 OCR 기록 보기', '수동 확정 해제'가 표시됩니다. '주간 점수 수정' 창에 정확한 하루 점수를 입력하고 확인하세요. 빈칸으로 저장하면 수동 확정을 해제하여 자동 계산을 다시 적용합니다.

과업 점수 수정은 이후 날짜의 주간 누적 기준에도 영향을 줄 수 있으므로 관련 날짜를 함께 확인하세요. 흙먼지 수동 점수는 0부터 설정한 일일 최대점수 범위여야 합니다. 주간 점수 수정은 관리 기록을 고치는 기능이며 원래 캡처한 OCR 원본 자체를 바꾸지는 않습니다.

12. 닉네임·별칭 관리

같은 길드원이 OCR에서 '닉네임A'와 '닉네임B'로 다르게 읽히면 한 길드원에게 별칭으로 연결합니다. 연결 후 주간 시트에는 대표 닉네임 한 행으로 표시됩니다. 대표 닉네임을 바꾸면 관련 주간 시트에도 새 이름이 반영됩니다.

주간 시트의 닉네임 셀을 클릭해 두 행을 순서대로 선택하고 '선택한 2명 합치기'를 누를 수도 있습니다. 첫 번째로 선택한 잘못 읽힌 이름을 두 번째로 선택한 기준 닉네임에 연결할지 확인하세요. 같은 길드원의 동일 날짜 값이 같으면 중복 합산하지 않습니다. 값이 다르면 자동 합산하지 않고 날짜별로 유지할 점수를 선택하게 됩니다. 잘못된 자동 합산이나 별도 행이 보이면 별칭 연결과 날짜별 선택 결과를 확인하세요.

13. CSV 저장 및 내보내기

공적치 계산·흙먼지 계산 탭의 'CSV 저장'은 현재 OCR 결과 표를 저장합니다. 저장 대화상자에서 파일 위치를 선택할 수 있습니다. 과업 주간·흙먼지 주간 탭의 '주간 CSV 내보내기'는 조회 중인 주간 결과를 내보냅니다. 자동 주간 내보내기 위치는 %LOCALAPPDATA%\GFL2GuildOCR\weekly_exports 입니다. CSV를 열어 닉네임, 날짜, 점수, 미확정 표시가 기대한 대로 나오는지 확인하세요.

14. 데이터 저장 위치

사용자 데이터 폴더:
%LOCALAPPDATA%\GFL2GuildOCR

주간 기록은 weekly_records.db에, 백업은 backups에, 캡처 이미지는 captures에, 주간 CSV는 weekly_exports에 저장됩니다. 업데이트 관련 기록이 있으면 update.log가 생성될 수 있습니다. 이 폴더는 실행 파일이 들어 있는 프로그램 폴더와 별개입니다. 새 프로그램으로 교체하더라도 사용자 데이터 폴더를 지우지 않으면 기록은 별도로 남습니다.

15. 현재 주간 초기화

과업 주간 또는 흙먼지 주간에서 조회 주간을 먼저 확인한 뒤 '현재 주간 초기화'를 선택합니다. 확인 후 선택한 종류와 조회 중인 해당 주의 주간 점수, 선택·수정 결과 및 해당 주간 내보내기 CSV가 초기화됩니다. 다른 종류의 시트나 다른 주의 기록은 대상이 아닙니다. 캡처에서 읽은 OCR 원본 기록은 남지만 주간 반영 결과는 다시 만들어야 합니다. 잘못 초기화하지 않도록 조회 주간과 종류를 꼭 확인하고, 필요하면 먼저 DB와 CSV를 백업하세요.

16. 업데이트

도움말 → 업데이트 확인에서 새 공개 버전을 확인할 수 있습니다. 현재 설치본보다 높은 공개 버전이 나오면 사용자 승인 후 파일을 내려받고 검증한 다음, 사용자 DB를 백업하고 별도 업데이터가 프로그램을 교체합니다. GitHub 계정이나 토큰은 필요하지 않습니다. 이전 프로그램 및 DB 백업은 복구를 위해 보관되며 임시 다운로드 파일은 정리될 수 있습니다.

v0.1.3에 포함된 업데이터는 한글·공백 등 원하는 설치 폴더 이름을 유지한 채 교체할 수 있습니다. GFL2GuildOCR.exe 파일 이름과 _internal 등 프로그램 구성은 유지하세요. v0.1.1·v0.1.2의 기존 업데이터에는 폴더명 제한이 남아 있어, 구버전 설치 폴더 이름을 변경했다면 업데이트가 실패할 수 있습니다. 모든 앱을 종료한 후 설치 폴더 이름을 GFL2GuildOCR로 임시 변경하여 업데이트하고(기존 폴더를 덮어쓰지 마세요), v0.1.3 설치가 끝나면 다시 원하는 이름으로 바꿀 수 있습니다. 또는 검증된 폴더명 패치 업데이터를 사용하세요. 사용자 데이터 폴더 %LOCALAPPDATA%\GFL2GuildOCR는 삭제하거나 초기화하지 마세요. 기존 v0.1.2 ZIP은 소급 변경하지 않습니다.

17. 백업 및 복구

중요한 작업 전에는 프로그램을 종료하고 %LOCALAPPDATA%\GFL2GuildOCR 폴더의 weekly_records.db와 backups 폴더를 안전한 위치에 복사해 두세요. 업데이트 과정에서도 DB 및 이전 프로그램 백업이 생성될 수 있습니다. 새 버전을 실행한 뒤에는 DB 형식이 바뀔 수 있으므로 프로그램 폴더만 임의로 구버전으로 되돌리지 마세요. 복구가 필요하면 프로그램을 종료한 상태에서 백업 시점과 버전이 맞는지 확인한 뒤 진행하세요.

18. 문제 해결

- 게임 창이 창 목록에 없으면 게임을 실행한 상태에서 '창 목록 새로고침'을 누릅니다. 창이 최소화되어 있다면 복원하세요.
- 캡처가 검게 나오거나 다른 화면이면 게임 창을 복원하고, 가능하면 앞에 놓은 뒤 다시 캡처하세요. 일부 게임 렌더링 방식에서는 다른 창 뒤에 있을 때 화면을 읽지 못할 수 있습니다.
- 닉네임이나 숫자가 잘못 읽히면 OCR 결과 셀을 더블클릭해 고친 후 주간에 반영하세요. 별칭이 반복된다면 길드원 관리에서 연결하세요.
- 주간 시트에 미등록 닉네임이 있으면 길드원 관리에서 새로 등록하거나 기존 길드원에 연결하세요.
- '?' 또는 '? 누적...'가 있으면 셀의 상태 / 근거 보기와 관련 OCR 기록 보기를 확인하세요. 조건이 맞으면 전날 OCR 근거 확인 후 점수 반영을, 근거가 확실한 다른 경우에는 점수 수동 확정을 사용하세요.
- 업데이트 확인이 실패해도 기존 프로그램과 데이터는 계속 사용할 수 있습니다. 인터넷 연결을 확인한 뒤 다시 시도하세요.
- EXE만 복사한 뒤 실행되지 않으면 공식 ZIP 전체를 다시 압축 해제하고 GFL2GuildOCR 폴더 구성을 유지하세요.
- Windows SmartScreen 경고가 보이면 공식 배포 페이지에서 받은 파일인지 먼저 확인하세요. 신뢰할 수 없는 출처의 파일은 실행하지 마세요.

20. 첫 실행 확인

먼저 기존 실행본과 실제 DB의 수동 사전 백업 경로를 확인합니다. 첫 실행 시 자동 migration backup도 별도로 생성될 수 있습니다. 오래된 공적 weekly/Accepted/State/Choice/Raw/CSV는 최근 4주 정책에 따라 정리될 수 있으나 Dust Raw/Accepted/Manual/Event/Settlement history는 대상이 아닙니다.

① 공식 ZIP 전체 압축 해제 → ② 기존 길드원·별칭·공적·흙먼지 기록 확인 → ③ 과업 주간별 일일 기준 확인 → ④ 종료·재실행 후 기록 유지 확인

자동 확정 행은 실제 Daily 숫자로, 미확정 합계는 '?'로 보여야 합니다. 이벤트 중 탈퇴자가 있다면 [탈퇴]/회색/이후 X 및 탈퇴일까지 점수 합산을 확인합니다. 확인을 위해 실제 데이터를 일부러 조작하지 마세요.

문제가 있으면 앱을 종료하고 오류 화면과 작업 순서를 알려주세요. DB 복구와 구버전 복귀는 앱을 종료한 뒤 별도 확인을 거쳐 진행합니다.

21. 2026-09-27 추가 수정: 탈퇴자 결산

- 도중 탈퇴 여부는 실제 탈퇴 시각(left_at)과 이벤트 종료 시각(end_at)을 비교합니다. left_at < end_at일 때만 아래 예외를 적용하며, 정확히 종료 시각에 탈퇴한 경우부터는 기존 확정 규칙을 유지합니다. 일요일 02:00~04:59가 마지막 게임 날짜에 속하더라도 종료 후 탈퇴로 판단합니다.
- 이벤트 도중 탈퇴한 길드원은 탈퇴 전 기록된 유효한 일일 점수를 결산에 포함합니다. 기존 일일 점수만 남아 있는 경우에도 서로 충돌하지 않고 0점 이상 일일 최대점수 이하인 정수이면 반영합니다.
- 탈퇴 전 날짜에 점수와 계산 상태가 모두 없는 경우, 그 날짜는 결산 합산에서 제외합니다. 빈칸에 임의의 0점이나 OCR 근거를 저장하지 않습니다. 탈퇴 이후 X 날짜도 합산하지 않습니다.
- 이미 미확정/대기/BASELINE 상태가 존재하거나 별칭 기록이 충돌하는 경우, 또는 기존 점수가 음수·최대점수 초과인 경우에는 계속 사용자 확인이 필요합니다.
- 활동 중인 길드원과 이벤트 종료 후 탈퇴한 길드원의 기존 확정 규칙은 바꾸지 않았습니다. 일반 OCR 미확정 처리 개선은 다음 흙먼지 이벤트 작업으로 남겨 둡니다.
- 이번 수정은 탈퇴자를 삭제하거나 기존 OCR·수동 점수·닉네임 기록을 변경하지 않습니다. 결산은 사용자가 프로그램에서 직접 실행합니다.
